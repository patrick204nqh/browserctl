# v0.16 — Clean: execution plan

**Status:** IN-PROGRESS

> Companion to v0.15 ("Lock"). v0.15 introduced the consolidated `data` verb
> alongside deprecated `cookie *` and `storage *` aliases. v0.16 deletes the
> aliases and tidies the back-compat scaffolding that was kept only to bridge
> the deprecation window.

## Goal

Remove every surface that v0.15 marked "Removed at 1.0" and drop the
incidental back-compat scaffolding that was kept around solely to bridge the
v0.15 deprecation cycle. v0.16 is the cleanup release that hardens the v1.0
surface before the soak window ends.

The plan's previous v1.0-cut.md (per v0.15 plan §1.0) is superseded by this
plan — the "Removed at 1.0" deletions land in v0.16 instead, and the v1.0
cut becomes a no-code release that simply bumps the version.

## Non-goals

- New user-facing commands or workflow features.
- Any new public surface area. v0.16 is strictly subtractive (plus tests/docs).
- Touching the API stability zones beyond removing things already
  deprecated. Nothing moves between Fixed / Stable / Experimental in this
  cycle.

## Dependencies

- v0.15 must be released. (`Patrick` reports done.)
- The two-month soak that would normally precede 1.0 collapses into the v0.16
  release window. Anyone consuming the deprecated aliases must migrate by
  v0.16; the `Removed at 1.0` text in `docs/reference/api-stability.md` is
  rewritten to read `Removed in v0.16`.

## Conventions for every PR in this plan

- Branch off `main`, open a PR, never push to `main`.
- Conventional Commits: `chore!:` / `refactor:` / `test:` / `docs:`. Use
  `chore!:` for any commit that drops a public surface (the alias verbs are
  the obvious one) and tag it with a `BREAKING CHANGE:` footer plus
  `Release-As: 0.16.0`.
- No `Co-Authored-By` lines. No "Generated with Claude Code" or AI
  attribution.
- Public surface diff check: every PR runs the v0.14 lock-file spec. PR 1
  updates the lock-file in the same commit.

## WS-1 · Drop deprecated cookie/storage surface

**Outcome:** The `cookie *` and `storage *` verbs are gone — from the CLI,
the wire protocol, the Ruby client, the docs, and the lock-file. The only
way to read or mutate browser-side persistent data is `data --scope ...`.

### PR 1 · `chore!: remove deprecated cookie and storage verbs`

The single marquee PR of v0.16. Deletes:

- `lib/browserctl/commands/cookie.rb`
- `lib/browserctl/commands/storage.rb`
- `lib/browserctl/commands/deprecation_notice.rb`
- The deprecated client methods on `lib/browserctl/client.rb`
  (`cookies`, `set_cookie`, `delete_cookies`, `import_cookies`,
  `export_cookies`, `storage_get`, `storage_set`, `storage_delete`,
  `storage_export`, `storage_import`).
- Any `cookie *` / `storage *` dispatch in
  `lib/browserctl/server/command_dispatcher.rb`.
- The thin delegator versions of
  `lib/browserctl/server/handlers/cookies.rb` and
  `lib/browserctl/server/handlers/storage.rb` if their only remaining
  responsibility is delegation. If they retain logic that
  `Handlers::Data` calls into, keep the file but rename it under
  `handlers/data/` and delete the public wire entry points.
- `spec/unit/commands/deprecation_notice_spec.rb`.
- All specs in `spec/integration/cookies_spec.rb` and
  `spec/integration/storage_spec.rb` whose coverage is already mirrored
  by `spec/integration/data_command_spec.rb` (delete; do not leave
  duplicate coverage).

Updates:

- `spec/fixtures/public_surface.yml` — delete the eleven entries marked
  `# deprecated, remove at 1.0 — see ADR-0021` (both `fixed_zone:` and
  the CLI verb lists).
- `docs/reference/api-stability.md` — replace `Removed at 1.0` references
  with `Removed in v0.16`. Move the "Cookies (deprecated v0.15, …)" and
  "Storage (deprecated v0.15, …)" sections into a single historical
  paragraph: "Removed in v0.16, see ADR-0021."
- `docs/reference/commands.md` — delete the `## Cookie (deprecated, …)`
  and `## Storage (deprecated, …)` sections wholesale.
- `docs/architecture/decisions/0021-data-verb-consolidation.md` — append a
  status line at the top: `Status: Accepted — implemented v0.15, aliases
  removed v0.16.`

**Acceptance:**

- `grep -rn "cookie\b\|storage\b" lib/browserctl/commands/` returns
  nothing (filenames or contents).
- The public surface spec (`spec/public_surface_spec.rb`) passes against
  the updated lock-file with zero drift.
- `bundle exec rspec` is green (0 failures).
- A migration shim that calls `browserctl cookie list` exits with a
  clean "unknown command" error from the CLI parser — no half-removed
  alias path.

**Commit footer:** `BREAKING CHANGE: deprecated cookie/storage verbs
removed; use data --scope.` and `Release-As: 0.16.0`.

**Risk:** Medium. Largest deletion in v0.16. The alias path has been
exercised in CI for one minor release; removal is purely subtractive.

## WS-2 · Drop back-compat scaffolding

**Outcome:** Code kept around solely to bridge v0.14→v0.15 transitions is
gone. No "shim", no "alias", no `# deprecated` comment in `lib/`.

### PR 2 · `refactor: drop session.page back-compat shim`

`PageSession` exposed `session.page` as a passthrough to the Ferrum page;
v0.15 PR 8 extracted `PageDriver`, kept `session.page` as a back-compat
shim returning `driver.raw_page`. The only caller was a single unit spec
(`spec/unit/page_session_spec.rb`). Rewrite that spec against `session.driver`
and delete the shim.

**Files:**

- `lib/browserctl/server/page_session.rb` — drop the `page` method and the
  raw-Ferrum-page constructor branch (constructor accepts only a
  `PageDriver` going forward).
- `spec/unit/page_session_spec.rb` — rewrite against `session.driver`.

**Acceptance:** `grep -rn "session.page\b\|raw_page\b" lib/ spec/` returns
no hits outside the driver implementation itself.

**Risk:** Low.

### PR 3 · `chore: drop --store local|session wire short-forms`

The wire protocol accepts `local` and `session` as v0.15-only short-form
aliases for `--scope localStorage|sessionStorage` (per the data handler).
v0.16 removes the short-form parser and the corresponding spec coverage.

**Files:**

- `lib/browserctl/server/handlers/data.rb` — remove the short-form
  expansion in the scope validator.
- `spec/integration/data_command_spec.rb` — remove the short-form examples.
- `docs/reference/api-stability.md` and `docs/architecture/decisions/0021-data-verb-consolidation.md` —
  drop the `--store local|session` references.

**Acceptance:** Sending `--scope local` over the wire returns an
`INVALID_ARGUMENT` typed error with a hint pointing at the long form.

**Risk:** Low.

## WS-3 · Code hygiene

**Outcome:** The TODOs that have been around long enough to gather dust are
either resolved or converted into tracked issues. The codebase has no
floating `# TODO:` comment older than v0.13.

### PR 4 · `chore: resolve or file TODOs in recording / trace`

Audit:

- `lib/browserctl/recording.rb:83` — the `TODO: ref-based` instruction is
  emitted into generated workflows. It is a user-facing instruction, not
  a code TODO; rename the marker so a casual grep does not flag it as
  unfinished work. Suggested: `REVIEW: …`.
- `lib/browserctl/trace/event_stream.rb:61` — `TODO: stamp session_id on
  every log line`. Implement or remove. If implementing, scope is small;
  if removing, file an issue and replace the comment with the issue URL.
- `lib/browserctl/recording/workflow_renderer.rb:154,166,197` — same
  category as the `recording.rb` line: user-facing markers in generated
  output. Audit naming and consolidate.

**Files:** the affected library files and any spec that asserts on the
TODO string in generated workflows.

**Acceptance:** `grep -rn "^\s*#.*TODO" lib/` returns at most three lines,
each accompanied by an issue URL or a justifying comment.

**Risk:** Low.

### PR 5 · `chore: prune obsolete spec fixtures and dead helpers`

Sweep the `spec/support/` and `spec/fixtures/` directories for files
referenced by zero specs. Delete them. The plan does not enumerate
candidates — do a real audit.

**Files:** TBD by audit.

**Acceptance:** `git grep -L <path>` returns nothing for each deleted
fixture.

**Risk:** Low.

## Execution order

1. WS-1 PR 1 (the marquee deletion) — open first. Pin `Release-As: 0.16.0`.
2. **Parallel after PR 1 merges**: WS-2 PR 2, WS-2 PR 3, WS-3 PR 4, WS-3 PR 5.

There is no hard gate other than PR 1 — its removal of the `cookie *`/`storage *`
surface is what defines v0.16. Everything else is cleanup that could ship
independently in a later v0.16.x patch if needed.

## After v0.16

The two-month v1.0 soak resumes from the v0.16 release date. The v1.0 cut
becomes a no-code release that bumps the version and re-affirms the lock —
`docs/plans/v1.0-cut.md` will be a one-page changelog, not an execution plan.
